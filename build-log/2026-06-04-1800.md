## Test Pipeline Endpoint

`POST /api/test/pipeline/movie/{movie_id}` — downloads all TMDB posters, runs each stage, copies
survivors/rejects into nested subdirectories for visual inspection.

```
experiments/data/<movie>/  (or ocr-first/<movie>/)
├── <all w500 posters>
├── sha256/              ← SHA-256 survivors
├── sha256_rejected/     ← removed by SHA-256
└── sha256/
    ├── ocr/             ← OCR accepted
    ├── ocr_rejected/    ← OCR rejected (text-heavy)
    └── ocr/
        ├── phash/       ← pHash survivors
        ├── phash_rejected/ ← pHash removed
        └── phash/
            ├── clip/         ← top 5 (1.jpg–5.jpg, re-downloaded at original)
            └── clip_rejected/ ← rank 6+
```

**Key behaviors:**
- Downloads at w500 for fast processing, top 5 re-downloaded at original resolution
- Text-free posters (< 3 chars detected text) pushed to end of ranked list — only selected if < 5 textured posters exist
- Per-poster CLIP classification logging (with-text vs text-free, scores, filenames)
- PaddleOCR noise suppressed during OCR stage
- Negative filter currently DISABLED (`neg_threshold=2.0`)

**File:** `marquee/api/routes/test_pipeline.py`  
**Registered in:** `marquee/main.py`

## Issues Discovered & Decisions Made

### PaddleOCR Memory Crash
Using `"original"` TMDB size downloaded 4000–6000px images → PaddleOCR allocated massive tensors
→ single worker ballooned to 25 GB RAM → crash. Fixed by switching to `w500` downloads with
top-5 re-downloaded at original. Also tried `w780` as compromise but reverted to `w500`.

### pHash Threshold Too Conservative
`DEDUP_PHASH_THRESHOLD=6` let nearly-identical ensemble posters (same background/cast, slightly
different poses) through as "different." Raised to **8**.

### Text-Free Poster Handling
`PosterTextFilter` originally accepted text-free posters, then we made it reject them, which killed
Nosferatu (stylized gothic posters with unreadable titles). Current approach: OCR accepts text-free,
but CLIP repositions them to end of ranked list. Posters with < 3 chars detected text are
considered "text-free." Only one poster has clear "nosferatu" title — PaddleOCR can't read
stylized gothic text at w500.

### Pipeline Order
Tested SHA→pHash→OCR→CLIP vs SHA→OCR→pHash→CLIP. OCR-first is slower (processes more images)
but results are in `experiments/ocr-first/` for comparison.
